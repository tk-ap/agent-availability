# Agent Control — North Star

## Product definition

Agent Control continuously observes AI capacity across the portfolio, identifies what matters, and tells you what to do next.

## Core loop

OBSERVE → UNDERSTAND → CONTROL → ACT → LEARN

### OBSERVE
Gather evidence automatically from affiliated domains, product sites, APIs, connected systems, runtime signals, portfolio state, and future sensors.

### UNDERSTAND
Build evidence-backed models of products, agents, capabilities, dependencies, capacity, readiness, and intelligence gaps. Never fabricate unknowns.

### CONTROL
Surface the portfolio by attention state:
- ACT NOW
- REVIEW
- OPPORTUNITY
- HEALTHY

### ACT
Every important observation should produce a clear next action: investigate, fix, review, explore, create work, snooze, dismiss, or mark incorrect.

### LEARN
Actions and new evidence update the model over time.

## Assessment's role

Assessment is an intelligence mechanism, not the primary product experience. Replace manual questionnaires with evidence-backed inference and verification. Ask the user only when confidence is low and the information is important.

The preferred workflow is:

DISCOVER → PROFILE → VERIFY → ASSESS → WORK

## Evidence model

Every inferred claim should have:
- value
- confidence
- supporting evidence/provenance

Unknown must remain UNKNOWN.

High-confidence findings should require no manual entry. Low-confidence/high-impact findings should become targeted verification or investigation tasks.

## UI principle

The primary experience should answer: “What should I do next?”

Do not make the home screen a questionnaire or domain intake form. Domain scraping is a sensor feeding the intelligence layer, not the product itself.

## Capacity command center

The portfolio should expose overall AI capacity, attention states, and entity-level control views. Entity views should show observed facts, knowns, unknowns, evidence, capacity/readiness, and recommended actions.

## Anti-drift rules

- Do not turn Agent Control into a generic assessment/intake application.
- Do not require users to manually describe information that can be inferred from evidence.
- Do not make readiness scores the product; scores support decisions.
- Preserve portfolio-wide context, capacity, readiness, neglect prevention, and action-oriented command-center behavior.
- Prefer automatic observation and targeted human verification over forms.
